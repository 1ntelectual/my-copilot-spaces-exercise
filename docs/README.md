# OctoAcme Project Management Docs

This README provides a quick reference and navigation index for all OctoAcme program and project management process documentation.

## Summary of Project Management Processes

OctoAcme follows a structured, lifecycle-based approach to project management that emphasizes customer value, iterative delivery, and clear ownership. The organization applies a five-phase model—**Initiation**, **Planning**, **Execution**, **Release**, and **Close & Retrospective**—to all cross-functional projects. This framework is grounded in core principles of customer-first prioritization, data-informed decision-making, psychological safety, and transparency.

Key roles are clearly defined to ensure accountability and effective collaboration. The **Project Manager** coordinates delivery activities and manages schedules and risks. The **Product Manager** defines what should be built, prioritizes the backlog, and measures outcomes. **Developers** implement features and participate in code reviews. **QA/Testing** validates quality against acceptance criteria. Communication happens through weekly PM-PdM syncs, twice-weekly standups for the delivery team, and monthly stakeholder updates.

Execution and quality are managed through disciplined workflows and continuous improvement. Teams use GitHub Projects to track work through defined columns, follow small pull request conventions with automated CI testing and security scanning, and maintain strong quality gates including unit tests, integration tests, and end-to-end smoke tests. Risk management is continuous, with risks captured in a register and reviewed weekly. After each sprint or release, retrospectives capture learnings and convert them into actionable improvements, creating a culture of continuous learning and iteration.
